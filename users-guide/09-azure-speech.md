# 09 Azure Speech による音声認識（任意）

音声認識には、ブラウザ標準の音声認識のほかに、Azure Speech（Microsoft の音声認識サービス）を使う方式があります。
Azure Speech を使うには、利用者が用意した Azure Speech のリソースの **エンドポイント** と **キー** を設定画面で保存します。
キーは中継サーバーだけが保管し、画面・ブラウザ・ファイルには表示も保存もされません。

> この文書の例はすべてプレースホルダです。`<リソース名>` や `<キー>` は、ご自分の値に読み替えてください。実際のキーをこの文書やチャット・メールに書かないでください。

## 準備

1. Azure Portal で Speech（または Azure AI サービス）のリソースを作り、キーとエンドポイントの画面で次の 2 つを確かめます。
   - エンドポイント: `https://<リソース名>.cognitiveservices.azure.com`（カスタムドメイン）、またはリージョン名（例: `japaneast` のような英小文字と数字）
   - キー: `<キー>`（キー 1 かキー 2 のどちらか）
2. 中継サーバーを起動してアプリを開きます（[01 導入と起動](01-getting-started.md) の `start.ps1` / `start.sh`）。Azure Speech の設定は中継サーバーが応答しているときだけ変更できます。

## エンドポイントとキーの保存

1. コマンドバーの［設定］（または Alt+Shift+F11）で設定画面を開きます。
2. 「Azure Speech（音声認識）」の欄の［接続先］に、エンドポイント（`https://<リソース名>.cognitiveservices.azure.com` かリージョン名）を入力します。
   - 受け付けるのは、https の Azure Speech のドメイン（`*.cognitiveservices.azure.com`、`*.api.cognitive.microsoft.com`、`*.stt.speech.microsoft.com`）と、リージョン名（英小文字と数字）だけです。http・ほかのドメイン・IP アドレス・localhost は、キーが意図しない宛先へ送られないように拒否されます。
3. ［キー］にキーを入力します。入力中の文字は伏せ字で表示されます。この欄はブラウザのパスワードの保存・自動補完の対象になりません。
4. ［保存］を押します（キーボードでは［保存］にフォーカスして Enter）。
   - 保存の操作の後は、成功・失敗にかかわらずキーの欄は空に戻ります。保存したキーは二度と表示されません。
   - ［設定状態］に「接続先:」とホスト名、「キー: 設定済み」が表示されます。
   - キーを保存すると、音声認識の方式が自動で Azure Speech に切り替わり、その旨が表示されます。

## キーの変更（置き換え）

- キーを変えるときは、［キー］に新しいキーを入力して［保存］を押します。古いキーは新しいキーに置き換わります。
- エンドポイントだけを変えるときは、［接続先］だけを入力して［保存］を押します（キーの欄が空なら、キーは変わりません）。

## キーの削除

1. ［削除］を押します。確認が表示されます。
2. ［キーを削除］を選ぶとキーが消え、［設定状態］が「キー: 未設定」になります。［キャンセル］では何も消えません。
   - キーを削除すると、音声認識の方式はブラウザ標準に戻ります。エンドポイントは残ります。
   - ［データ初期化］（会議の内容の消去）では、エンドポイントとキーは消えません。

## 接続テスト

- エンドポイントとキーを保存した後、［接続テスト］を押すと、中継サーバーが Azure Speech にキーの確認だけを問い合わせます。会議の音声や文字は送りません。
- 10 秒以内に「接続テスト: 成功」か、失敗とその理由（未設定・認証・接続・タイムアウト）が表示されます。接続テストの結果で、方式・同意・図は変わりません。

## 方式の切替

- 設定画面の［認識方式］で「ブラウザ標準」か「Azure Speech」を選びます。初期値はブラウザ標準です。
- Azure Speech は、エンドポイントとキーが設定済みのときだけ選べます。未設定のときは選べない理由が表示されます。
- 選んだ方式はこのブラウザに保存され、再読込の後も保たれます。セッションファイルには含まれません。

## 同意

- Azure Speech では、会議の音声が中継サーバーを通して Azure Speech（設定したエンドポイントのホスト）へ送られます。
- そのため、方式が Azure Speech のときは［記録開始］の近くに同意のチェックと送信先のホスト名が表示されます。同意するまで音声は送られません。
- 同意は保存されません。再読込・方式の切替・エンドポイントの変更の後は、もう一度同意が必要です。

## 失敗したときの対処

| 表示 | 原因と確認すること |
|---|---|
| 中継サーバーが応答しない | 中継サーバー（`start.ps1` / `start.sh`）が起動しているかを確認し、画面を再読込します。応答しない間は設定を変更できません |
| 保存できない（エンドポイントが正しくない） | https の Azure Speech のドメインかリージョン名かを確認します。保存済みの設定は変わっていません |
| 接続テスト: 失敗（未設定） | エンドポイントとキーを保存してから、もう一度接続テストを行います |
| 接続テスト: 失敗（認証） | キーが正しいか、リソースのキーを再生成していないかを確認し、新しいキーを保存して置き換えます |
| 接続テスト: 失敗（接続）／（タイムアウト） | エンドポイントのホスト名とネットワーク（プロキシ・ファイアウォール）を確認し、再試行します |
| 音声認識が止まった | 状態表示の再試行の操作で Azure Speech をもう一度試すか、ブラウザ標準に切り替えます。記録中の発話と図は失われません |

## キーの保管について

- キーは中継サーバーのある PC の `config/azure-speech.local.json`（環境変数 `RELAY_SPEECH_STORE` で変更可）にだけ保存されます。このファイルは git の管理外（.gitignore）です。
- Windows では、現在のユーザーに結び付いた OS の暗号化（DPAPI）で保存されます。ほかの OS では、所有者だけが読み書きできる権限（0600）で保存されます。
- 別のユーザーや別の PC にファイルをコピーしても、Windows ではキーを復号できません。その場合は設定画面でキーを保存し直してください。

## キー操作

| 操作 | キー |
|---|---|
| 設定画面を開く | Alt+Shift+F11 |
| Azure Speech の設定を保存（入力した接続先・キー） | Ctrl+Alt+Shift+V |
| Azure Speech の接続テスト | Ctrl+Alt+Shift+T |
| Azure Speech のキーを削除（確認が表示されます） | Ctrl+Alt+Shift+Z |

確認の表示では Esc でキャンセルできます。

## 図の再配置の周期

- 図は、新しい要素を周期を待たずにすぐ（暫定の位置に）表示し、一定の周期ごとに配置を決め直します（再配置）。
- 再配置の周期の初期値は 10 秒です。前の再配置の後に新しい要素が加わっていなければ、再配置は行いません。
