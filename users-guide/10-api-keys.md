# 10 接続キー（Microsoft Foundry・GitHub Copilot・Azure Speech）

外部サービスのキーと GitHub Copilot の認証は、画面の一番上の **［接続キー］** から開く「接続キー」画面で登録します。
［設定］（レイアウトと描画スタイル・LLM のプロバイダーを選ぶ画面）とは別の画面です。

> この文書の例はすべてプレースホルダです。`<リソース名>`・`<キー>`・`<トークン>` は、ご自分の値に読み替えてください。実際のキー・トークンをこの文書やチャット・メールに書かないでください。

## 開き方と閉じ方

- 開く: 画面最上部のコマンドバーにある、鍵のアイコンの **［接続キー］**（説明文字「Foundry・Azure Speech のキーと GitHub Copilot の認証を登録します」つき）を押します。キーボードでは Ctrl+Alt+Shift+H です。
- 画面の中央にダイアログが開き、背後の画面はグレーがかったオーバーレイで覆われます。開いている間、背後の操作はできません（記録・音声認識は止まらず、図も変わりません）。
- 閉じる: 右上の［閉じる］（×）、ダイアログ内の［閉じる］、または Esc キーです。閉じると、フォーカスは［接続キー］のボタンに戻ります。
- オーバーレイをクリックしても閉じません（入力中のキーを誤って失わないためです）。
- 閉じると、保存していない入力欄の値は破棄され、開き直しても復元されません。

## 画面の見かた

左に分類の一覧（**Microsoft Foundry**・**GitHub Copilot**・**Azure Speech**）、右に選んだ分類の内容が並びます。分類は、クリックか、一覧にフォーカスして上下の矢印キーで切り替えます。画面が狭いときは、一覧と内容が縦に並びます。

## Azure Speech の分類の使い方

1. 分類の一覧で［Azure Speech］を選びます。
2. ［接続先］にエンドポイント（`https://<リソース名>.cognitiveservices.azure.com` かリージョン名）を入力します。
3. ［キー］に `<キー>` を入力します（入力中は伏せ字です）。
4. ［保存］を押します。保存の後、キーの欄は空に戻り、状態に「接続先:」のホスト名と「キー: 設定済み」が表示されます。
5. ［接続テスト］で、保存した内容で接続できるかを確かめられます。
6. キーを消すときは［削除］を押し、確認で［キーを削除］を選びます。

この分類で保存した内容は、［設定］画面の「Azure Speech（音声認識）」の項目と同じ保管先を共有するので、どちらで保存しても、もう一方の状態に反映されます。詳しい使い方は [09 Azure Speech](09-azure-speech.md) を見てください。

## Microsoft Foundry の分類の使い方

1. 分類の一覧で［Microsoft Foundry］を選びます。
2. ［キー］に `<キー>` を入力して［保存］を押します。保存の後は欄が空に戻り、状態が「キー: 設定済み」（出どころは「画面で保存」）になります。キーの値は二度と表示されません。設定済みのときに新しいキーを保存すると、置き換わります。
3. 削除は［削除］を押し、確認で［キーを削除］を選びます。環境変数・設定ファイルで設定したキーは画面から削除できません（その旨が表示されます）。
4. データの初期化（［データ初期化］）では、キーは消えません。キーを保存しても、LLM 連携は有効になりません（［設定］の LLM 連携の切り替えは別です）。

中継サーバーが応答していないときは、キーを変更できず、理由が表示されます。中継サーバー（`start.ps1` / `start.sh`）を起動してから開き直してください。

## GitHub Copilot の分類の使い方

LLM 連携のモデルに GitHub Copilot を使うときだけ必要な設定です。Microsoft Foundry だけを使う場合は、この節の作業は要りません。

### LLM のプロバイダーの選び方

LLM 連携で Microsoft Foundry と GitHub Copilot のどちらを使うかは、**［設定］** 画面の LLM のプロバイダーの選択で選びます（初期値は Microsoft Foundry）。この「接続キー」画面では、選んだプロバイダーの認証を登録します。

### 利用の前提

- GitHub Copilot の利用権（Copilot のプランの契約）が必要です。
- LLM 連携の要求（図の要点の抽出・図の生成・接続テスト）は、GitHub Copilot の利用量（premium requests など）に数えられます。
- 同意の確認では、送信先が「GitHub Copilot」と表示されます。Microsoft Foundry への同意とは別に同意します。

### GitHub Copilot SDK の導入（GitHub Copilot を使うときだけ）

中継サーバーは、GitHub Copilot SDK（Python 版。GitHub Copilot CLI を介してモデルを呼びます）を使います。SDK は任意の依存で、導入しなくても中継サーバーは起動し、Microsoft Foundry は使えます。

1. 中継サーバーを動かす Python（3.11 以上）で、リポジトリの一番上のフォルダーから次を実行します。

   ```
   python -m pip install -r server/requirements-copilot.txt
   ```

2. 中継サーバー（`start.ps1` / `start.sh`）を起動し直します。
3. ［接続キー］の［GitHub Copilot］を開き、「SDK」の状態が「導入済み」になったことを確かめます。導入されていないときは、その旨と導入の手順の案内が表示されます。

### 認証方式

［認証方式］で次のどちらかを選び、［保存］を押します。

- **GitHub アカウントでサインイン（既定）**: アプリにキーなどを登録せずに、GitHub のアカウントでサインインします。資格情報は Copilot CLI が OS の資格情報の保管庫に保存し、このアプリは保存も表示もしません。同じ PC の Copilot CLI ですでにサインインしていれば、操作なしに **サインイン済み（アカウント名）** と表示されます。
- **トークン**: GitHub のトークンを登録します。トークンの欄は、認証方式がトークンのときだけ入力できます。

［モデル名］は任意です。空のときは GitHub Copilot SDK の既定のモデルを使います。

### サインインの手順（確認のページと確認コード）

1. 認証方式が「GitHub アカウントでサインイン」で、状態が「未サインイン」のとき、［サインイン］（GitHub でサインイン）を押します。
2. 画面に **確認のページの URL**（`https://github.com/login/device`）と、**確認コード**（`XXXX-XXXX` の形）が表示されます。［コピー］で確認コードをクリップボードへ写せます。
3. 確認のページのリンクを押すと、新しいタブで GitHub のページが開きます。確認コードを入力し、内容を確かめて承認します（組織で SAML SSO を使っているときは、組織ごとの承認も求められます）。
4. 承認すると、画面を再読込しなくても、状態が **サインイン済み（アカウント名）** になります。
5. やめるときは［取り消し］を押します。確認コードの期限切れ・拒否・取り消し・失敗のときは原因が表示され、状態は未サインインのままです。もう一度［サインイン］から始められます。

### トークンを使う場合

- 使えるトークンは、**fine-grained personal access token**（`github_pat_` で始まるもの。個人のアカウントが所有し、アカウントの権限 **Copilot Requests** を付けたもの）などです。
- **classic の personal access token（`ghp_` で始まるもの）は、GitHub Copilot SDK（Copilot CLI）が受け付けません。**
- 画面で登録する: 認証方式を［トークン］にし、［トークン］に `<トークン>` を入力して［保存］を押します。保存の後、欄は空に戻り、状態が「トークン: 設定済み」（出どころは「画面で保存」）になります。トークンの値は二度と表示されません。中継サーバーが、Foundry のキーと同じく、利用者だけが読める形で封をして保存します。
- 環境変数で設定する: 中継サーバーを起動する前に、`COPILOT_GITHUB_TOKEN`（または `GH_TOKEN`・`GITHUB_TOKEN`。この順に優先）を設定します。認証方式は `COPILOT_AUTH_METHOD=token`、モデル名は `COPILOT_MODEL` で設定できます。

  ```
  # PowerShell の例（値はプレースホルダ）
  $env:COPILOT_AUTH_METHOD = "token"
  $env:COPILOT_GITHUB_TOKEN = "<トークン>"
  ```

- 値の優先順位は、環境変数 ＞ `config/llm.local.json` ＞ 画面での保存 です。環境変数・設定ファイルで設定した項目は、画面から変更・削除できません（状態に出どころが「環境変数」「設定ファイル」と表示されます）。
- 認証方式が「サインイン」のときは、ほかの用途で `GITHUB_TOKEN` などが設定されていても、中継サーバーはトークンを使わず、サインイン済みの資格情報を使います。

### 削除

［削除］を押し、確認で［設定を削除］を選ぶと、画面で保存した認証方式・モデル名・トークンが消え、認証方式はサインインに戻ります。データの初期化（［データ初期化］）では、これらの設定は消えません。
