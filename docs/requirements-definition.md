## 1. 概要

### 1.1 事業背景

会議の話し合いを手で描き残すグラフィックレコーディング／グラフィックファシリテーションは、描き手の確保が難しい。会議中の音声から話の内容を自動で図式化し、その場の参加者が見ながら話し合えるようにする。グラフィックレコーディングは言葉と絵で話を整理して「記録」することを目的とし、グラフィックファシリテーションは話し手の様子や感情を映して場の主体性と創発を促すことを目的とする（SRC-001）。本アプリは両方の考え方を取り入れる。

### 1.2 目的

| ID | 目的 | 成功指標 | 測定方法 |
|---|---|---|---|
| G-001 | 会議中の発話を、ほぼリアルタイムに、シーンごとの要点と図として画面に表示する | 発話確定から表示まで {PARAM-001} 秒以内 | NFR-PERF-001 の AC |
| G-002 | 外部通信なしに、ブラウザ内だけで動作する（音声認識が使えない環境にも代替がある） | 全機能の利用中の外部リクエスト 0 件 | NFR-OFFLINE-001 の AC |
| G-003 | 表示内容を PDF・画像で持ち出し、2D/3D とダイナミックカメラでプレゼンテーションできる | 保存と提示の全手段が機能する | FR-006、FR-007、FR-009、FR-010 の AC |

### 1.3 事業妥当性の判定

条件付き。条件: ブラウザの音声認識（Web Speech API）が音声を外部サービスへ送る実装がある。外部通信なしの目的（G-002）との整合は Q-001 の回答で確定する。それまで音声認識の利用は承認待ちとし、代替入力（FR-002）だけで目的を満たせる構成にする。費用・市場の数値は入力になく、記載しない。

## 2. 対象と対象外

- 対象: 単一端末のブラウザで動く静的 Web アプリ。会議の話し合いの記録・図式化・表示・保存・提示。言語は日本語（既定）と英語。
- 対象外: 複数端末での共同編集、サーバー保存、利用者認証、外部の AI・クラウドサービスによる要約、話者の識別、会議の録音ファイルの保存。

## 3. 前提・制約

### 3.1 既定制約（要求定義プロンプトの常設方針）

- ui_policy-1 利用者がレイアウトを変更できるモダンな UI（決定状態: 承認済み・既定制約）
- ui_policy-2 ペルソナごとの既定の情報表現（決定状態: 承認済み・既定制約）

### 3.2 パラメータ（PARAM）

閾値・期間・件数などの値は、要求と受入基準に直接書かず、ここで定義して `{PARAM-xxx}` の形で参照します。

| ID | 名前 | 値 | 単位 | 根拠 | 決定状態 |
|---|---|---|---|---|---|
| PARAM-001 | 発話確定から表示までの上限 | 3 | 秒 | 依頼の「ほぼリアルタイム」を観察可能にする補い。PARAM の変更で戻せる | 承認済み（包括承認 2026-10-14・approval_policy） |
| PARAM-002 | シーン分割の無音間隔 | 20 | 秒 | 話題の区切りの目安として補った値。PARAM の変更で戻せる | 承認済み（包括承認 2026-10-14・approval_policy） |
| PARAM-003 | 取込ファイルの上限サイズ | 1 | MB | ブラウザ内処理の応答性を保つ補い | 承認済み（包括承認 2026-10-14・approval_policy） |
| PARAM-004 | プレゼンでの 1 シーンの既定の滞在時間 | 8 | 秒 | 提示の標準的な間合いとして補った値 | 承認済み（包括承認 2026-10-14・approval_policy） |

### 3.3 用語

| 用語 | 定義 | 禁止同義語 |
|---|---|---|
| セッション | 1 回の会議の記録単位。発話とシーンの集まり | なし |
| 発話 | 入力源から確定して届いた 1 まとまりの文字列 | なし |
| シーン | 同じ話題でまとまる発話の区間。1 シーンが画面上の 1 つの絵になる | なし |
| 要点 | シーンの発話から抽出した短い語句 | なし |
| 入力源 | 発話を供給する経路（音声認識、手入力、ファイル取込）。差し替え・注入できる抽象 | なし |
| レイアウト | 画面の各パネルの位置・大きさ・表示状態の組 | なし |

### 3.4 状態

| 対象エンティティ | 状態 | 遷移の条件 |
|---|---|---|
| セッション | 準備中→記録中→一時停止→停止 | 開始操作で記録中、一時停止操作で一時停止、停止操作で停止 |
| シーン | 進行中→確定 | 無音間隔 {PARAM-002} 超過、話題の切替、または利用者の操作で確定 |
| 発話 | 記録中 | セッションが記録中のときだけ、入力源からの確定結果が発話として追加される |

### 3.5 [ASSUMPTION]

- 技術方針（依頼の推奨）: ビルド不要の静的 Web アプリ、依存はリポジトリ同梱、CDN 不使用。要求としての外部通信禁止は NFR-OFFLINE-001。

## 4. ペルソナ

| ペルソナ | 業務 | 主要な判断 | 使うデータ | 判断の頻度と緊急度 | 役割 | 出典 |
|---|---|---|---|---|---|---|
| ファシリテーター | 会議を進行し、話の流れを整理して場に返す | 話題を切り替えるか、論点が出尽くしたか | 発話、シーン、要点 | 会議中に常時。高 | なし（認証なしのローカルアプリ） | SRC-001 |
| 会議参加者 | 画面を見て話の全体像と経緯を確認する | 話が脱線していないか、決まったことは何か | シーンの絵、要点 | 会議中・会議後。中 | なし（認証なしのローカルアプリ） | SRC-001 |

## 5. 利用シナリオ

- 主要: ファシリテーターが言語を選び記録を開始し、会議の発話がシーンごとの図として画面に増えていく。会議後に PDF・画像で保存する。
- 代替: 音声認識が使えない、または使わない場合は、手入力またはファイル取込で発話を渡す。
- 提示: 2D/3D を切り替え、ダイナミックカメラでシーンを順に提示する。
- 中断と再開: 一時停止・再開、およびブラウザ再読込後の復元（FR-012）。
- 失敗と復旧: マイク拒否、音声認識非対応、不正なファイルは、内容を失わずに理由と代替手段を示す。

### 6.1 機能要求

#### FR-001 音声認識による発話の取込
- 要求: ファシリテーターは、記録中にデバイスのマイクの音声から、ブラウザの Web Speech API が使える範囲で、発話を入力源として取り込める。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の中心機能）
- 上位: G-001　出典: 依頼原文、SRC-003
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-001: 注入した入力源（テスト用の疑似音声認識）が確定結果を 1 件送ったとき、セッションが記録中なら、その文字列が発話として 1 件追加される。実マイクは不要で検証できる。
  - 検証レベル: system
- 受入基準 AC-002: Web Speech API が使えない環境、またはマイクの許可が拒否された環境で、利用者に理由と代替手段（FR-002）が表示され、既に記録した内容は失われない。
  - 検証レベル: integration
- 受入基準 AC-003: 音声認識の暫定結果は確定結果と区別して表示され、確定結果だけが発話として記録される。
  - 検証レベル: integration
- 受入基準 AC-039: 音声認識の言語は、選択中の表示言語（FR-008）に一致する。言語を切り替えると、次の認識から切替後の言語が使われる。
  - 検証レベル: integration

#### FR-002 代替入力（手入力・ファイル取込）
- 要求: 利用者は、音声認識を使えない・使わないときに、手入力のテキストまたはテキストファイルの取込で、音声と同じ入力源として発話を渡せる。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（音声認識が使えない環境の代替を依頼が求めている）
- 上位: G-001　出典: 依頼原文　
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: PARAM-003
- 関連する既存資産: なし
- 受入基準 AC-004: 手入力欄に入力して送信すると、入力した文字列が発話として 1 件追加され、入力欄が空に戻る。
  - 検証レベル: system
- 受入基準 AC-005: テキストファイル（.txt）を取り込むと、行ごとに発話が順に追加される。取込可能な上限サイズは {PARAM-003} とする。
  - 検証レベル: system
- 受入基準 AC-006: 上限を超えるファイル、テキストでないファイル、空のファイルを取り込むと、原因を示すメッセージが表示され、既存の発話は変わらない。
  - 検証レベル: integration

#### FR-003 発話のシーン分割と要点抽出
- 要求: システムは、発話の列から、シーンと各シーンの要点を、外部通信なしに自動で作る。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（「各シーンで話してきた内容を記録・図式化」の前提）
- 上位: G-001　出典: 依頼原文、SRC-001
- 対象エンティティ: シーン　関係する状態: 進行中→確定　参照パラメータ: PARAM-002
- 関連する既存資産: なし
- 受入基準 AC-007: 同じ発話列を入力すると、毎回同じシーン分割と同じ要点が得られる（決定的）。要点は各シーンの発話に含まれる語句だけから成る。
  - 検証レベル: unit
- 受入基準 AC-008: 直前の発話から {PARAM-002} 秒を超える無音間隔があったとき、または利用者が「次のシーン」を操作したとき、進行中のシーンが確定し、次の発話から新しいシーンが始まる。
  - 検証レベル: integration

#### FR-004 2D のグラフィック・ファシリテーション表示
- 要求: 利用者は、シーンごとの見出し・要点・要点間の関係線を、2D の拡大・縮小・移動できるキャンバス上の図として見られ、発話者の感情や様子を示す語が話にあるときは、その表現が絵記号として添えられる。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の中心機能）
- 上位: G-001　出典: 依頼原文、SRC-001
- 対象エンティティ: シーン　関係する状態: 進行中→確定　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-009: 発話が追加されると、進行中のシーンの図が更新され、新しい要点が画面上に表示される。
  - 検証レベル: system
- 受入基準 AC-010: 各シーンが、見出し 1 つ、要点 1 件以上、関係線を持つ 1 つのまとまりとして、時系列の順に並んで表示される。
  - 検証レベル: system
- 受入基準 AC-011: 感情・様子を示す語（例: 「モヤモヤ」「困った」。語彙は日本語・英語それぞれ組み込みの辞書）を含む発話があるシーンに、その語に対応する絵記号と語が表示される。該当語がなければ表示されない。
  - 検証レベル: integration

#### FR-005 図の手修正
- 要求: ファシリテーターは、自動で作られた要点の編集・削除、要点の追加、シーンの結合・分割を手で行える。
- 決定状態: 承認済み（包括承認 2026-10-14・approval_policy）　出自: AI提案　優先度: SHOULD（自動抽出の誤りをその場で直さないと、図が場の合意とずれるため）
- 上位: G-001　出典: SRC-001（話し合いの場を映すことが目的）
- 対象エンティティ: 要点　関係する状態: なし　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-012: 要点を編集・削除・追加し、シーンを結合・分割すると、表示に反映される。以後の自動処理で、手修正した要点が上書きされない。
  - 検証レベル: integration

#### FR-006 画像としての保存
- 要求: 利用者は、画面にレンダリングされた図を、画像ファイル（PNG と SVG）として保存できる。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の保存要求）
- 上位: G-003　出典: 依頼原文
- 対象エンティティ: シーン　関係する状態: なし　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-013: 保存操作で PNG ファイルが得られ、画像として開けて、画面の図のすべてのシーンの見出しと要点を含む。
  - 検証レベル: system
- 受入基準 AC-014: 保存操作で SVG ファイルが得られ、図の見出しと要点の文字列がテキストとして含まれる。
  - 検証レベル: integration

#### FR-007 PDF としての保存
- 要求: 利用者は、画面にレンダリングされた図を、PDF ファイルとして保存できる。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の保存要求）
- 上位: G-003　出典: 依頼原文
- 対象エンティティ: シーン　関係する状態: なし　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-015: 保存操作で、PDF として開けるファイルが得られ、図の全シーンの見出しと要点を含む。
  - 検証レベル: system
- 受入基準 AC-016: PDF の生成中に、外部へのリクエストが 0 件である。
  - 検証レベル: system

#### FR-008 表示言語の切替（日本語・英語）
- 要求: 利用者は、起動後にいつでも、表示言語を日本語（既定）と英語で切り替えられる。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の要求）
- 上位: G-001　出典: 依頼原文
- 対象エンティティ: セッション　関係する状態: 準備中→記録中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-017: 初回起動時の表示言語は日本語である。
  - 検証レベル: system
- 受入基準 AC-018: 言語を英語に切り替えると、画面上のすべての操作名・メッセージが英語になり、日本語に戻すと日本語になる。ページの再読込は不要である。
  - 検証レベル: system
- 受入基準 AC-019: 言語を切り替えても、記録済みの発話・シーン・要点と、記録中の状態が失われない。
  - 検証レベル: system

#### FR-009 2D/3D の切替表示
- 要求: 利用者は、同じシーンのデータを 2D 表示と 3D 表示のどちらでも見られ、切り替えても選択中のシーンが保たれる。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の要求）
- 上位: G-003　出典: 依頼原文
- 対象エンティティ: シーン　関係する状態: なし　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-020: 2D から 3D に切り替えると、全シーンが奥行きのある空間に配置されて表示され、切り替え前に選択していたシーンが選択されたままである。3D から 2D へも同様である。
  - 検証レベル: system
- 受入基準 AC-021: 3D 表示が使えない環境（WebGL なし）で、3D の代替表示または 2D 表示が使われ、その旨が表示される。
  - 検証レベル: integration

- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の要求）
- 上位: G-003　出典: 依頼原文

- 関連する既存資産: なし
- 受入基準 AC-033: アプリは音声データを保存せず、セッションの保存内容と PNG・SVG・PDF のいずれにも音声が含まれない。
