## 1. 概要

### 1.1 事業背景

会議の話し合いを手で描き残すグラフィックレコーディング／グラフィックファシリテーションは、描き手の確保が難しい。会議中の音声から話の内容を自動で図式化し、その場の参加者が見ながら話し合えるようにする。グラフィックレコーディングは言葉と絵で話を整理して「記録」することを目的とし、グラフィックファシリテーションは話し手の様子や感情を映して場の主体性と創発を促すことを目的とする（SRC-001）。本アプリは両方の考え方を取り入れる。

### 1.2 目的

| ID | 目的 | 成功指標 | 測定方法 |
|---|---|---|---|
| G-001 | 会議中の発話を、ほぼリアルタイムに、シーンごとの要点と図として画面に表示する | 発話確定から表示まで {PARAM-001} 秒以内 | NFR-PERF-001 の AC |
| G-002 | 外部通信なしに、ブラウザ内だけで動作する（アプリ自身の外部リクエスト 0 件。音声認識の既定はデバイス内処理で、音声が外部へ送られる可能性は、利用者の明示的な同意があるときだけ。使えない環境には代替入力がある） | 全機能の利用中（音声認識を有効にした場合を含む）のアプリ自身の外部リクエスト 0 件。かつ、デバイス内処理が使えない環境で、同意なしに音声認識が開始されることが 0 件 | NFR-OFFLINE-001 の AC-031、NFR-PRIV-001 の AC-034、FR-001 の AC-067 |
| G-003 | 表示内容を PDF・画像で持ち出し、2D/3D とダイナミックカメラでプレゼンテーションできる | 保存と提示の全手段が機能する | FR-006、FR-007、FR-009、FR-010 の AC |

### 1.3 事業妥当性の判定

条件付き。条件: ブラウザの音声認識（Web Speech API）が音声を外部サービスへ送る実装がある。外部通信なしの目的（G-002）との整合は Q-001（推奨 A 採用、2026-10-14）で確定した: 音声認識はデバイス内処理が提供される場合に使い、提供されない場合は外部送信の可能性への利用者の明示的な同意があるときに限り使える（2026-10-14 の依頼で変更）。いずれでもなければ代替入力（FR-002）だけで目的を満たす。費用・市場の数値は入力になく、記載しない。

## 2. 対象と対象外

- 対象: 単一端末のブラウザで動く静的 Web アプリ。会議の話し合いの記録・図式化・表示・保存・提示。言語は日本語（既定）と英語。
- 対象外: 複数端末での共同編集、サーバー保存、利用者認証、外部の AI・クラウドサービスによる要約、話者の識別、会議の録音ファイルの保存。

## 5. 利用シナリオ

- 主要: ファシリテーターが言語を選び記録を開始し、会議の発話がシーンごとの図として画面に増えていく。会議後に PDF・画像で保存する。
- 代替: 音声認識が使えない、または使わない場合は、手入力またはファイル取込で発話を渡す。
- 提示: 2D/3D を切り替え、ダイナミックカメラでシーンを順に提示する。
- 中断と再開: 一時停止・再開、およびブラウザ再読込後の復元（FR-012）。
- 失敗と復旧: マイク拒否、音声認識非対応、不正なファイルは、内容を失わずに理由と代替手段を示す。

### 6.1 機能要求

#### FR-001 音声認識による発話の取込
- 要求: ファシリテーターは、記録中にデバイスのマイクの音声から、選択中の表示言語（FR-008）の音声認識だけを判定の対象として（他の言語の可否は問わない）、発話を入力源として取り込める。(1) ブラウザがその言語のデバイス内処理（processLocally 等）を提供するときは、デバイス内処理で使える。言語モデルが未導入（downloadable／downloading）のときは、導入してから使う。(2) デバイス内処理を提供しないが、ブラウザが音声認識 API（SpeechRecognition／webkitSpeechRecognition）を持つときは、「音声がブラウザ提供元の音声認識サービスへ送られる可能性がある」ことに利用者が明示的に同意（既定は未同意）した場合に限り、開始できる。同意前は開始しない。この場合は processLocally を要求しない。(3) どちらでもないときは無効化され、代替入力（FR-002）へ誘導される（2026-10-14 の依頼で Q-001 A を変更。NFR-PRIV-001 に従属）。音声認識の状態は「使えます（デバイス内）」「使えます（要同意・外部送信の可能性）」「使えません」に区別して示し、理由（API 非対応／言語未対応／モデル未導入／同意待ち／マイク拒否）を伝える。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の中心機能）
- 上位: G-001　出典: 依頼原文、SRC-003
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-001: 注入した入力源（テスト用の疑似音声認識）が確定結果を 1 件送ったとき、セッションが記録中なら、その文字列が発話として 1 件追加される。実マイクは不要で検証できる。
  - 検証レベル: system
- 受入基準 AC-002: Web Speech API が使えない環境、またはマイクの許可が拒否された環境で、利用者に理由と代替手段（FR-002）が表示され、既に記録した内容は失われない。
  - 検証レベル: integration
- 受入基準 AC-003: 音声認識の暫定結果は確定結果と区別して表示され、確定結果だけが発話として記録される。
  - 検証レベル: integration
- 受入基準 AC-040: ブラウザが音声認識 API を持たない、または選択中の言語を認識できない環境では、音声認識の開始操作は無効になり、理由と代替入力（FR-002）への誘導が表示され、音声認識は開始されない。デバイス内処理が使えず音声認識 API がある環境では、利用者の同意（AC-067）がない間は開始されない。判定は選択中の言語だけで行い、他の言語の可否に左右されない。
  - 検証レベル: integration
- 受入基準 AC-066: 選択中の言語のデバイス内処理が使える（processLocally が真）ときは従来どおり processLocally を真にして開始し、同意は求めない。言語モデルが導入可能／導入中のときは、導入が完了してから開始し、導入に失敗したときは理由（モデル未導入）と代替入力（FR-002）を示す。
  - 検証レベル: integration
