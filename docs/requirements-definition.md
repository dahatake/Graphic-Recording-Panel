## 1. 概要

### 1.1 事業背景

会議の話し合いを手で描き残すグラフィックレコーディング／グラフィックファシリテーションは、描き手の確保が難しい。会議中の音声から話の内容を自動で図式化し、その場の参加者が見ながら話し合えるようにする。グラフィックレコーディングは言葉と絵で話を整理して「記録」することを目的とし、グラフィックファシリテーションは話し手の様子や感情を映して場の主体性と創発を促すことを目的とする（SRC-001）。本アプリは両方の考え方を取り入れる。

### 1.2 目的

| ID | 目的 | 成功指標 | 測定方法 |
|---|---|---|---|
| G-001 | 会議中の発話を、ほぼリアルタイムに、シーンごとの要点と図として画面に表示する | 発話確定から表示まで {PARAM-001} 秒以内 | NFR-PERF-001 の AC |
| G-002 | 外部通信なしに、ブラウザ内だけで動作する（アプリ自身の外部リクエスト 0 件。音声認識の既定はデバイス内処理で、音声が外部へ送られる可能性は、利用者の明示的な同意があるときだけ。使えない環境には代替入力がある） | 全機能の利用中（音声認識を有効にした場合を含む）のアプリ自身の外部リクエスト 0 件。かつ、デバイス内処理が使えない環境で、同意なしに音声認識が開始されることが 0 件 | NFR-OFFLINE-001 の AC-031、NFR-PRIV-001 の AC-034、FR-001 の AC-067 |
| G-003 | 表示内容を PDF・画像で持ち出し、2D/3D とダイナミックカメラでプレゼンテーションできる | 保存と提示の全手段が機能する | FR-006、FR-007、FR-009、FR-010、FR-020、FR-021 の AC |

### 1.3 事業妥当性の判定

条件付き。条件: ブラウザの音声認識（Web Speech API）が音声を外部サービスへ送る実装がある。外部通信なしの目的（G-002）との整合は Q-001（推奨 A 採用、2026-10-14）で確定した: 音声認識はデバイス内処理が提供される場合に使い、提供されない場合は外部送信の可能性への利用者の明示的な同意があるときに限り使える（2026-10-14 の依頼で変更）。いずれでもなければ代替入力（FR-002）だけで目的を満たす。費用・市場の数値は入力になく、記載しない。

## 2. 対象と対象外

- 対象: 単一端末のブラウザで動く静的 Web アプリ。会議の話し合いの記録・図式化・表示・保存・提示。言語は日本語（既定）と英語。
- 対象外: 複数端末での共同編集、サーバー保存、利用者認証、外部の AI・クラウドサービスによる要約、話者の識別、会議の録音ファイルの保存。

### 6.1 機能要求

#### FR-001 音声認識による発話の取込
- 要求: ファシリテーターは、記録中にデバイスのマイクの音声から、選択中の表示言語（FR-008）の音声認識だけを判定の対象として（他の言語の可否は問わない）、発話を入力源として取り込める。(1) ブラウザがその言語のデバイス内処理（processLocally 等）を提供するときは、デバイス内処理で使える。言語モデルが未導入（downloadable／downloading）のときは、導入してから使う。(2) デバイス内処理を提供しないが、ブラウザが音声認識 API（SpeechRecognition／webkitSpeechRecognition）を持つときは、「音声がブラウザ提供元の音声認識サービスへ送られる可能性がある」ことに利用者が明示的に同意（既定は未同意）した場合に限り、開始できる。同意前は開始しない。この場合は processLocally を要求しない。(3) どちらでもないときは無効化され、代替入力（FR-002）へ誘導される（2026-10-14 の依頼で Q-001 A を変更。NFR-PRIV-001 に従属）。音声認識の状態は「使えます（デバイス内）」「使えます（要同意・外部送信の可能性）」「使えません」に区別して示し、理由（API 非対応／言語未対応／モデル未導入／同意待ち／マイク拒否）を伝える。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: MUST（依頼の中心機能）
- 上位: G-001　出典: 依頼原文、SRC-003
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: なし
- 関連する既存資産: なし
- 受入基準 AC-001: 注入した入力源（テスト用の疑似音声認識）が確定結果を 1 件送ったとき、セッションが記録中なら、その文字列が発話として 1 件追加される。実マイクは不要で検証できる。
  - 検証レベル: system
- 受入基準 AC-002: Web Speech API が使えない環境、またはマイクの許可が拒否された環境で、利用者に理由と代替手段（FR-002）が表示され、既に記録した内容は失われない。
  - 検証レベル: integration
- 受入基準 AC-003: 音声認識の暫定結果は確定結果と区別して表示され、確定結果だけが発話として記録される。
  - 検証レベル: integration
- 受入基準 AC-040: ブラウザが音声認識 API を持たない、または選択中の言語を認識できない環境では、音声認識の開始操作は無効になり、理由と代替入力（FR-002）への誘導が表示され、音声認識は開始されない。デバイス内処理が使えず音声認識 API がある環境では、利用者の同意（AC-067）がない間は開始されない。判定は選択中の言語だけで行い、他の言語の可否に左右されない。「言語未対応」（選択中の言語を認識できない）は日本語・英語以外の言語に限り、日本語・英語は対象外である（日本語・英語では、音声認識 API があれば言語未対応を理由に無効にならず、デバイス内処理の可否に応じて、開始できるか、同意待ち（AC-067）になる）。
  - 検証レベル: integration
- 受入基準 AC-066: 選択中の言語のデバイス内処理が使える（processLocally が真）ときは従来どおり processLocally を真にして開始し、同意は求めない。言語モデルが導入可能／導入中のときは、導入が完了してから開始し、導入に失敗したときは理由（モデル未導入）と代替入力（FR-002）を示す。
  - 検証レベル: integration
- 受入基準 AC-067: デバイス内処理が使えず音声認識 API がある環境（日本語・英語は「言語未対応」の対象外で、常にこの経路で扱う。AC-040）では、音声が外部の音声認識サービスへ送られる可能性がある旨（日本語・英語の表示言語に合わせた文言）を示し、利用者が明示的に同意した後にだけ開始できる。既定は未同意で、同意前は開始せず、同意後も processLocally を設定しない。同意を取り消せ、取り消すと認識は停止する。同意はそのページの利用中（再読込までのセッション内）だけ有効で、保存されず、再読込後の既定は未同意に戻る［ASSUMPTION: 利用者が覆せる。根拠: 外部送信の同意を永続させない方が安全］。

- 受入基準 AC-068: 同意の操作（トグルまたは確認ダイアログ）は、キーボードだけで操作でき、状態が支援技術に伝わり、色だけで示されない（NFR-A11Y-001）。同意状態は保存しない（AC-067 のとおりメモリのみで、再読込後は未同意に戻る）。音声データは、ブラウザ内の保存（FR-012）にもセッションファイル（FR-019）にも含めない。認識文字列は、FR-012 のブラウザ内の保存には含めず、セッションファイル（FR-019）には含めて復元する。本 AC の「セッションの保存」は FR-012 のブラウザ内の保存に限る。
  - 検証レベル: integration
- 受入基準 AC-069: 音声認識の状態表示は「使えます（デバイス内）」「使えます（要同意・外部送信の可能性）」「使えません」を区別し、使えない・開始できないときは、API 非対応／言語未対応／モデル未導入／同意待ち／マイク拒否のうち該当する理由を示す。
  - 検証レベル: integration
- 受入基準 AC-039: 音声認識の言語は、選択中の表示言語（FR-008）に一致する。言語を切り替えると、次の認識から切替後の言語が使われる。
  - 検証レベル: integration

- 上位: G-001　出典: 依頼原文　
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: PARAM-003
- 関連する既存資産: なし
- 受入基準 AC-004: セッションが記録中のとき、手入力欄に入力して送信すると、入力した文字列が発話として 1 件追加され、入力欄が空に戻る。

#### FR-022 字幕ファイル（.vtt）の取込
- 要求: 利用者は、Teams 会議などの字幕・文字起こしファイル（WebVTT、拡張子 .vtt）を取り込み、cue（字幕の 1 区間）ごとの発話テキストを、ファイルの順に発話として追加できる。話者名とタイムスタンプは発話に含めない。
- 決定状態: 承認済み（依頼 2026-10-14）　出自: 依頼原文　優先度: SHOULD（議事録・会議の文字起こしを図にしたい利用者の入力経路。.txt 取込の拡張で、新しい入力経路は作らない）
- 上位: G-001　出典: 依頼原文、FR-002、SRC-009
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: PARAM-002、PARAM-003
- 関連する既存資産: 共通部品「アプリ組立」（FR-002、FR-013 も使用）、機能 FR-002（web/src/input.js の取込処理）
- 受入基準 AC-113: セッションが記録中のとき、Teams 形式の .vtt（`00:00:01.000 --> 00:00:05.000` の行と、`<v 話者名>発話</v>` 形式の本文を持つ cue が複数ある）を取り込むと、cue ごとに本文のテキストだけが、ファイルの順に確定結果の発話として 1 件ずつ追加される。追加された発話に話者名・タイムスタンプの文字列は含まれない。.vtt の取込入口は FR-002・FR-013 と共通のファイル取込操作（右パネルの取込操作を含む）で、取込んだ発話は認識文字列の一覧に確定結果として並ぶ。発話の受付時刻は、最初の cue を取込時刻とし、以降の cue は開始時刻の差だけ取込時刻から相対的に遅らせて与える（時刻が読めない cue と、直前より前に戻る cue は直前の cue の時刻を使う）。これにより {PARAM-002} を超える開始時刻の差がある cue の間でシーンが分かれる（AC-008 と同じ規則）。.vtt の最初の cue は取込時刻を受付時刻とするため、取込直前の発話との間隔が {PARAM-002} を超えれば通常どおりシーンが分かれる（無音間隔で分割しない noGapSplit は .txt の取込だけに適用する）。受付時刻は発話テキストには含めない。AC-044 は .txt のみに適用する。.txt の取込（AC-005）は変わらない。拡張子の大文字小文字は区別しない。取込可能な上限サイズは {PARAM-003} とする。
  - 検証レベル: system
- 受入基準 AC-114: .vtt の次の要素は発話にならず、取込が失敗もしない。先頭の WEBVTT ヘッダ行（BOM と、WEBVTT に続く同じ行の文字列を含む）、NOTE・STYLE・REGION のブロック、cue 識別子の行（GUID などの文字列）、`-->` の行の後ろの cue 設定。cue 本文の `<v …>`、`</v>`、`<c>`、`<i>`、`<b>`、`<u>`、`<lang>`、`<ruby>`、`<00:00:03.000>` のタグは取り除かれ、文字参照（&amp; &lt; &gt; &nbsp;）は元の文字になる。1 つの cue の本文が複数行のときは、1 つの発話として半角スペースでつなぐ。本文が空（話者タグだけ、空白だけを含む）の cue は発話にならない。
  - 検証レベル: integration
- 受入基準 AC-115: セッションが記録中でない（準備中・一時停止・停止）とき、.vtt の取込は AC-042 と同じく受け付けられず、「記録を開始・再開してください」と表示される。選択したファイルは保たれ、発話は追加されない。
  - 検証レベル: integration
- 受入基準 AC-116: 上限 {PARAM-003} を超える .vtt、先頭が WEBVTT ではない（拡張子だけ .vtt の）ファイル、テキストとして読めないファイル、発話になる cue が 1 件もないファイルを取り込むと、原因（大きすぎる／WebVTT ではない／空）を示すメッセージが表示され、既存の発話は変わらない（AC-006 と同じ扱い）。
  - 検証レベル: integration
- 受入基準 AC-117: .vtt から取込んだ話者名は、画面（認識文字列の一覧、図）、保存物（PNG・SVG・PDF、セッションファイル）、ブラウザ内の保存データのどれにも現れない（話者識別は対象外）。取込の間、外部のオリジンへのリクエストは 0 件である。
  - 検証レベル: integration

#### FR-023 字幕ファイル取込の処理中表示と再取込
- 要求: 利用者は、.vtt（および .txt）のファイルを取り込む間、処理中であること・進み具合・結果（追加した発話の件数、または取り込めなかった理由と次の操作）を画面で確認でき、取り込めなかったときは同じファイルを選び直して取り込める。
- 決定状態: 承認済み（依頼 2026-10-15）　出自: 依頼原文　優先度: MUST（依頼の「.vtt の読み込みが動作していないように見える」の是正。処理の有無・失敗理由が見えないと、動作していないと区別できないため）
- 上位: G-001　出典: 依頼原文、FR-022、FR-002、SRC-010
- 対象エンティティ: 発話　関係する状態: 記録中　参照パラメータ: PARAM-014、PARAM-001、PARAM-003
- 関連する既存資産: 機能 FR-022（web/src/input.js、web/src/vtt.js）、機能 FR-002、機能 FR-013、機能 FR-014、共通部品「アプリ組立」
- 受入基準 AC-118: セッションが記録中の状態で、AC-113 を満たす .vtt を取り込むと、取込開始から {PARAM-014} 秒以内に、処理中であることを示す表示が出る。処理の進み具合（処理済みの cue 数と全 cue 数、または割合）が処理の間更新され、完了または失敗で処理中の表示は消える。
  - 検証レベル: system
