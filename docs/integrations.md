# 外部連携カタログ

このアプリが API・ファイル・DB・イベントなどで行う、外部のアプリ・データとの連携を、1 連携 1 項目で記録します。外部連携がないアプリは、このファイルを使わなくてかまいません（任意です）。
追加・変更・廃止は rd-author だけが行い、変更は要求定義書の変更履歴に記録します。ID は `python scripts/next-id.py INT` でだけ採番します。検査は `python scripts/verify.py --docs-only` です。

## 書式

見出しは `#### INT-001 <名前>` の形式で、その下に「欄名: 値」の箇条書きを書きます。

- 必ず値を書く欄: 連携先、方向（受信／送信／双方向）、方式、データ分類、個人情報（あり／なし）、認証認可、責任分界、状態（検討中／運用中／廃止）、関連する要求（FR-xxx、NFR-xxx-xxx）
- 次の欄は、値、`なし`、`TBD（Q-xxx）`（質問票の ID）のどれかで必ず埋めます: 頻度と量、可用性・SLA、レート制限、エラー・再試行・冪等性、契約・バージョン、変更通知、監視、データ保持、障害時の代替、法務・ライセンス
- 認証情報の値（トークン・パスワード・鍵・接続文字列）は、この文書に書きません。認証認可の欄には方式の名前を、「秘密の保管場所」の欄には保管場所の名前（例: Key Vault の名前）だけを書きます。値らしい文字列は検査が違反として報告します。
- チェックリストは `.github/skills/requirement-definition/integration-checklist.md` にあります。

  ```text
  #### INT-001 受注 API（例。実在する連携ではありません）
  - 連携先: 取引先 A の受注システム
  - 方向: 受信
  - 方式: REST（HTTPS）
  - データ分類: 取引データ（社外秘）
  - 個人情報: あり
  - 認証認可: OAuth 2.0 クライアントクレデンシャル
  - 秘密の保管場所: Key Vault（名前は運用手順書に記載）
  - 責任分界: 取引先 A が受注データの正確性、当社が受信後の保管と処理に責任を持つ
  - 状態: 検討中
  - 関連する要求: FR-012
  - 頻度と量: TBD（Q-010）
  - 可用性・SLA: なし
  - レート制限: なし
  - エラー・再試行・冪等性: なし
  - 契約・バージョン: なし
  - 変更通知: なし
  - 監視: なし
  - データ保持: なし
  - 障害時の代替: なし
  - 法務・ライセンス: なし
  ```

## 項目

#### INT-002 Microsoft Foundry（LLM 連携）
- 連携先: 利用者が設定した Microsoft Foundry のエンドポイント（ベース URL は https://<your-resource>.services.ai.azure.com/openai/v1 の形式、model はデプロイ名）
- 方向: 双方向
- 方式: REST（HTTPS、Responses API）。ブラウザからは直接呼ばず、ローカル中継サーバー（127.0.0.1・同一オリジンのみ）が中継する
- データ分類: 会議の発話の要点（利用者の社内情報を含み得る）
- 個人情報: あり（会話に含まれ得る。簡易マスキングは任意で完全ではない）
- 認証認可: API キー、または Microsoft Entra ID（az account get-access-token、スコープは ai.azure.com の .default）
- 秘密の保管場所: 環境変数、または git 管理外の config/llm.local.json（ブラウザには置かない）
- 責任分界: 利用者が送信に同意した範囲の内容の取り扱いは Foundry の契約に従い、アプリは送信の最小化・サニタイズ・自動復帰に責任を持つ
- 状態: 検討中
- 関連する要求: FR-062、FR-063、FR-065、FR-066、FR-067、NFR-SEC-003、NFR-SEC-004、NFR-PRIV-003
- 頻度と量: シーンの確定ごとに 1 回。1 回の送信は PARAM-070 の文字数以内
- 可用性・SLA: なし
- レート制限: なし
- エラー・再試行・冪等性: タイムアウト PARAM-069 秒。失敗は再試行せず現行ルールベース描画へ復帰（FR-062）
- 契約・バージョン: Responses API（バージョンの確認は未実施。SRC-057）
- 変更通知: なし
- 監視: なし（送信の履歴は件数と時刻だけ。NFR-PRIV-003）
- データ保持: アプリは送信内容を保存しない（AC-362）。Foundry 側の保持は契約に従う（未確認）
- 障害時の代替: 現行ルールベース描画（FR-062）
- 法務・ライセンス: なし（送信の可否・生成物の権利は利用者の組織の規程に従う。外部確認未実施）

#### INT-003 Azure Speech（音声認識）
- 連携先: 利用者が設定した Azure AI Speech のリソース（カスタムドメインのエンドポイント https://<リソース名>.cognitiveservices.azure.com/ の形式、またはリージョン名）の音声テキスト変換
- 方向: 双方向
- 方式: ブラウザからは直接呼ばず、ローカル中継サーバー（127.0.0.1・同一オリジンのみ。FR-066）が HTTPS（必要に応じて WebSocket）で中継する。中継の方式（WebSocket の橋渡し、短い音声の REST の分割送信、issueToken のトークンの利用など）は実装工程が選ぶ（SRC-064）
- データ分類: 会議の音声（参加者の声と発言内容。利用者の社内情報を含み得る）
- 個人情報: あり（音声と発言内容。アプリと中継サーバーは保存しない。NFR-PRIV-001、AC-446）
- 認証認可: リソースキー（中継サーバーだけが保持し、ブラウザへは返さない。設定画面での入力と保存の要求だけは NFR-SEC-005 の除外）。必要に応じて issueToken で 10 分間有効のアクセストークンに交換する（SRC-064）。リージョン名で設定したときは、キーはトークンの発行のホストにだけ付け、認識のホストにはトークンを付ける（AC-455）
- 秘密の保管場所: 中継サーバーの git 管理外の保管先（Windows は DPAPI による暗号化、それ以外は所有者のみの権限。NFR-SEC-005）。値はこの文書に書かない
- 責任分界: 利用者（リソースの所有者）がリソース・課金・キーの発行と失効・会議参加者への告知と送信の可否（組織の規程）に責任を持ち、アプリはキーの保管と非露出、送信前の同意、送信先の限定、音声の非保存、失敗時の停止と表示に責任を持つ
- 状態: 検討中
- 関連する要求: FR-081、FR-082、NFR-SEC-005、G-002、NFR-OFFLINE-001、NFR-PRIV-001
- 頻度と量: 方式が Azure Speech で記録中かつ同意済みの間、マイクの音声を連続して送る（量は会議の長さに比例）。接続テストは利用者の操作のたびに 1 回で、会議の内容を含まない
- 可用性・SLA: なし（Azure の SLA は未確認。障害時は FR-081 の AC-444 のとおり停止して理由を表示）
- レート制限: なし（Azure のクォータ・同時接続の上限は未確認。上限による拒否は接続または認証の失敗として扱う）
- エラー・再試行・冪等性: 未設定・認証・接続の失敗で音声認識を停止し、理由を表示する。自動の再試行とブラウザ標準への自動の切替はせず、利用者の 1 回の操作で再試行または切替（AC-444）。上流の正常な終了（無音による打ち切り・接続の時間の上限）とアクセストークンの期限切れは失敗に含めず、PARAM-008 秒以内に自動で再開する（AC-458）。接続テストは PARAM-074 秒で打ち切る（AC-450）
- 契約・バージョン: Azure AI Speech の音声テキスト変換（使う API と版は実装工程が確認する。SRC-064）
- 変更通知: なし
- 監視: なし（中継サーバーのログは件数・時刻・結果の分類だけで、音声・認識した文字列・キーを出さない。AC-446、AC-453）
- データ保持: アプリと中継サーバーは音声を保存しない（AC-446）。Azure 側は、リアルタイムの音声テキスト変換では音声と認識結果を保持・保存しない（SRC-066。2026-10-20 確認）。リソース側の診断ログなどの設定と契約による保持は利用者の責任（外部確認未実施）
- 障害時の代替: ブラウザ標準の音声認識（利用者の切替操作。FR-001 の条件に従う）、手入力、ファイル取込（FR-002、FR-022）
- 法務・ライセンス: なし（有料の利用は依頼 2026-10-20 で利用者が明示。会議参加者への告知・外部送信の可否は利用者の組織の規程に従う。外部確認未実施）

#### INT-004 GitHub Copilot（LLM 連携の GitHub Copilot SDK による呼び出し）
- 連携先: GitHub Copilot のサービス（中継サーバーの中で GitHub Copilot SDK（Python 版 github-copilot-sdk）を使い、SDK が管理する Copilot CLI がモデルを呼ぶ。SRC-074）
- 方向: 双方向
- 方式: 中継サーバーが SDK を呼び、SDK は Copilot CLI と JSON-RPC で通信し、Copilot CLI が GitHub へ HTTPS で接続する（SRC-074）。ブラウザからは直接呼ばない（127.0.0.1・同一オリジンのみ。FR-066）
- データ分類: 会議の発話の要点（利用者の社内情報を含み得る。INT-002 と同じ送信内容。NFR-PRIV-003）
- 個人情報: あり（会話に含まれ得る。画面には利用者自身の GitHub のアカウント名を表示する）
- 認証認可: GitHub アカウントでのサインイン（OAuth デバイスフロー。資格情報は Copilot CLI が OS の資格情報の保管庫に保存し、アプリは保存しない）、または GitHub のトークン（fine-grained personal access token・OAuth のユーザーのトークン。classic の personal access token は SDK が非対応。SRC-074）。GitHub Copilot の利用権が必要
- 秘密の保管場所: サインインは OS の資格情報の保管庫（Copilot CLI の管理）。トークンは環境変数、git 管理外の config/llm.local.json、または中継サーバーの git 管理外の保管先（DPAPI／0600。NFR-SEC-006）。値はこの文書に書かない
- 責任分界: 利用者が GitHub Copilot の契約・利用量（要求ごとに数えられる。SRC-074）・組織の規程に基づく送信の可否に責任を持ち、アプリは送信の最小化・プロバイダーごとの同意・ツールの無効化（AC-504）・秘密の非露出・失敗時の自動復帰に責任を持つ
- 状態: 検討中
- 関連する要求: FR-062、FR-068、FR-087、FR-088、NFR-SEC-006、NFR-PRIV-003
- 頻度と量: プロバイダーが GitHub Copilot で LLM 連携が有効・同意済みの間、シーンの確定ごとに 1 回（1 回の送信は PARAM-070 の文字数以内）。サインインと状態の確認は利用者の操作のたび、状態の取得のための Copilot CLI の起動と GitHub との通信は、プロバイダーが GitHub Copilot のとき、または接続キー画面の GitHub Copilot の分類を開いたときの要求のたびだけで（それ以外の状態の取得では起動しない。Q-034）、いずれも会議の内容を含まない（AC-507）。このアプリでのサインアウトは Copilot CLI の資格情報を消さない（AC-511。Q-033）
- 可用性・SLA: なし（GitHub 側の SLA は未確認。障害時は AC-506 のとおり現行ルールベース描画へ復帰）［ASSUMPTION: SLA を要求にしない。障害時も自動復帰で会議の進行は止まらないため。覆す条件: 利用者の組織が GitHub Copilot の可用性を業務の条件とするとき］
- レート制限: なし（GitHub Copilot の利用量の上限は未確認。上限による拒否は「利用の上限」の失敗として扱う。AC-506）［ASSUMPTION: 送信はシーンの確定ごとに 1 回で、上限への到達は失敗として扱えば足りる。覆す条件: 利用量の上限で会議中の利用が継続的に止まることが判明したとき］
- エラー・再試行・冪等性: タイムアウト PARAM-069 秒。失敗は再試行せず現行ルールベース描画へ復帰（FR-062、AC-506）。SDK 未導入・未サインイン・トークン未設定では送らない（AC-505、AC-506）
- 契約・バージョン: GitHub Copilot SDK（Python。github-copilot-sdk）と同梱の Copilot CLI。使う版の固定は実装工程が決める（SRC-074）
- 変更通知: なし
- 監視: なし（送信の履歴は件数と時刻だけ。NFR-PRIV-003）
- データ保持: アプリは送信内容を保存しない。GitHub 側の保持は契約に従う（外部確認未実施）［ASSUMPTION: GitHub 側の保持は利用者の契約の範囲で、アプリは送信の最小化（NFR-PRIV-003）とプロバイダーごとの同意（AC-513）で対処する。覆す条件: 利用者の組織の規程が GitHub 側の保持条件の確認を送信の前提とするとき］
- 障害時の代替: 現行ルールベース描画（FR-062）。利用者の操作でプロバイダーを Microsoft Foundry に切り替えられる（FR-068）
- 法務・ライセンス: なし（GitHub Copilot の利用規約と、外部送信の可否についての利用者の組織の規程に従う。外部確認未実施）［ASSUMPTION: 送信の可否の判断は利用者に委ね、アプリは既定オフと送信先を示した同意（FR-062）で判断の機会を与える。覆す条件: 利用者の指定］
- 状態の補足: 状態「検討中」は、FR-087・FR-088 が承認済み（依頼 2026-10-24）で実装前であることを示す（INT-002・INT-003 と同じ扱い）。実装と System Test の通過後に「運用中」へ改める
