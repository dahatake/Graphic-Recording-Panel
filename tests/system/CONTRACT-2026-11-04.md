# System Test 契約の改訂（2026-11-04 の利用者の依頼。run 202611040923）

`tests/system/CONTRACT.md`・`CONTRACT-FR077-078.md` の次の部分は、この文書で**置き換える**（食い違うときはこの文書が優先）。
期待値は要求定義書の受入基準だけから決めており、この文書は「テストが何を呼ぶか」だけを定める（内部構造は自由）。

## 1. 外部音声認識の同意は操作なし（口頭で得たものとして扱う）— AC-034・040・043・067・068・069・385・386・387・392・394・441・442・443・458

廃止するもの（呼べない／存在しない。テストは `undefined` であることを確かめる）:
- `app.setSpeechConsent`（同意の切替）、コマンド `speech.consent`（`app.commands`・`app.keymap` にない）。
- `web/index.html` の同意の操作要素 `#speech-consent`（チェックボックス・`role="switch"`/`checkbox`）、状態表示 `#speech-consent-state`、同意の `<label>`。ページ全体に、同意のための `input[type=checkbox]`・`role=switch|checkbox`・確認ダイアログはない。
- `startSpeech()` の `reason:'consent_required'`、`getSpeechStatus().reason:'consent'`（同意待ちは生じない）。

残る・変わるもの:
- `app.getSpeechConsent()` → **常に `true`**（起動直後・再読込後・方式の切替後・復元後・記録中以外のどれでも）。保存しない（`storage` に consent を含む値を書かない）。
- `startSpeech()`／`session.start`／`session.resume` の可否判定: `availabilityFor` が `remote`（判定不能の例外・未知の値を含む）→ **同意の確認なしで** `speechSource.start({lang})`（`processLocally` キーなし）。`local`→`start({lang, processLocally:true})`。`downloadable`・`unsupported`・`supported:false`・`mic_denied` は従来どおり。
- `app.getSpeechStatus()`: `remote` で API あり → `state:'consent'`（名前は維持）・`reason:null`・`startEnabled:true`・`text` は「使えます（要同意・外部送信の可能性）」を含む（同意は口頭で得るため「同意待ち」の理由は出ない）。`getCommandBar().status.speech` も `'consent'`（状態名のまま）。
- `app.getConsentUi()` → `{ visible:boolean, noticeVisible:boolean（visible と一致）, region:'top', nearCommand:'session.start', role:'note'|'status', interactive:false, colorOnly:false, notice:string }`。`checked`・`stateText`・`tabbable`・`label` は**持たない**（`undefined`）。`visible` は `getSpeechStatus().state==='consent'`（外部送信の可能性）のとき、`session` の状態によらず真。`local` では偽。`notice` は `app.t('speech.consent.notice')` と同じで、「外部」（en は `external`）と「口頭」（en は `verbal`）を含み、選択中の表示言語に従い `setLang` の直後に切り替わる。方式が Azure Speech のときは送信先のホスト名を含む（AC-442）。
- 実 DOM: 注意文は `#speech-consent-notice`（`role="note"` か `role="status"`。読み上げ対象で、`tabindex`・`button`・`input` を子に持たない）。`#speech-consent-box` は `visible` のとき表示、偽のとき `hidden`。
- 起動直後（`session==='preparing'`）に `speechSource.start` は 1 回も呼ばれない（利用者が `session.start` を実行するまで）。`session.pause`・`session.stop` は `speechSource.stop()` を呼び、`session.resume`・停止後の `session.start` は何も操作しなくても `speechSource.start` を呼ぶ（復元直後の `session.resume` も同じ）。
- `onend()` の自動再開（NFR-BG-001 AC-064）: `session==='recording'` かつ `availabilityFor` が `local` または `remote` のとき `start`（同意の条件は無い）。

## 2. 画風は常時表示の「画風」グループ（FR-077 AC-414〜417・459。旧 `drawStyle.pick`・一覧は廃止）

廃止するもの: コマンド `drawStyle.pick`、`app.getDrawStylePicker()`・`app.getDrawStylePickerView()`・`app.pickDrawStyle()`、`drawStyle.pick.*` のキー操作、`drawStyle.select.<id>`、画風の一覧要素（`#drawstyle-list`）、`valueLabel`。`app.commands`・`app.keymap`・`getCommandBar().items` のどれにもない。

- `getCommandBar().items` に、登録されたすべての描画スタイル（`getDrawStyles()` と同じ ID・並び。計 15。AC-670 の追加後）について `command:'drawStyle.set:<id>'`、`group:'drawStyle'` の項目がある。各項目: `label`（名前。`getDrawStyles()` の `label` と同じ。PARAM-011（全角 6／英語は半角 12）以内）、`labelVisible:true`、`accessibleName`（`label` と一致）、`description`（短い説明。非空。PARAM-170 以内）、`tooltip:{id,text}`（`text===description`）・`describedBy===tooltip.id`、`tabbable:true`、`tabIndex:0`、`pressed:boolean`（実 DOM の `aria-pressed="true|false"`。現在の描画スタイルだけ真）、`selectedMark:string|null`（現在のものだけ非空の文字列。色以外の印・枠）。ドロップダウン・開閉はない（`getCommandBar().items` は最初から 13 項目を含む）。
- `getCommandBar().groups` の `id:'drawStyle'`（ja 見出し「画風」）の `commands` は、上の 15 項目を `getDrawStyles()` の並びで並べたもの。
- `app.commands['drawStyle.set:<id>']()`（実 DOM では項目のクリック・Enter・Space）→ 同期で `getDrawStyle()===id`、`renderSvg()` のルート `data-draw-style===id`、その項目の `pressed` が真で他は偽、`getState().message.text` がその名前を含み（読み上げ対象）`getCommandBar().status.role==='status'`。`app.setDrawStyle(id)` も同じ結果（未知の ID・非文字列は `{ok:false}` で不変。従来どおり）。`app.commands['drawStyle.set:<id>']` は登録された ID だけにある。
- 変えないもの: 発話・シーン・要点・`getDiagramLayout()`・`getLayoutInfo()`・`getDetailLevel()`・`selectedSceneId`・`getState().session`・`input.draft`・`renderOutline()`、`getSettings().drawStyle`・`grp.settings`。
- コマンドの検索: `app.searchCommands(<描画スタイルの label>)`（ja・en）で `drawStyle.set:<id>` が見つかり、実行すると選ぶ。
- 狭い画面（AC-417）: `getCommandBarLayout({viewportWidth})` の `items` に 15 項目すべてがあり（省かれない。`overflowMenu` を持つ場合も、その `commands` に `drawStyle.set:*` は入らない）、各 `rect:{x,y,w,h}`・`labelLines>=1`、`scrollsHorizontally===false`。幅 1280px では `labelLines===1` で、ほかのどの項目の `rect` とも重ならない。
- リボンの操作 API: `app.operateBarItem('drawStyle.set:<id>')` は項目のクリックと同じ（`{ok:true}`。選んだ結果は上と同じ）。上部（リボン）での選択は［設定］の既定（`getSettings().drawStyle`・`grp.settings`）を変えない（FR-077 AC-418）。`setSettings({drawStyle})` で既定を変えると現在値もそれになり、押下の表示がそれに移る。`getSettingsDialog().fields` の `id:'drawStyle'` の `options` は 13 項目と同じ ID・名前・並び。［設定］のグループ（`settings`）には描画スタイルの項目を置かない（AC-459・519）。
- グループ順（AC-459）: `getCommandBar().groups` の `id` は順に `import`・`session`・`view`・`drawStyle`・`layoutType`・`settings`・`presentation`・`export`・`data`・`environment`（10 グループ）。`view` は `view.2d`・`view.3d`・`view.timeline`・`view.arrange`・`detail.next` の 5 つ（`drawStyle.pick` はない）。PARAM-092 は 13（1 グループの上限）。
- キーボード（AC-416。実 DOM）: 15 項目はすべて `button` で、Tab で順に到達でき、Enter・Space で選べる（クリックと同じ結果）。結果は `role="status"` の読み上げ領域（`#status` 相当。`getCommandBar().status`）に名前つきで出る。

## 3. 起動直後の記録ボタン（FR-072 AC-647）
- 起動直後（`preparing`）、`[data-command="session.start"]`・`[data-command="session.resume"]`（折りたたみ中の複製を含む）の `aria-pressed` は `"false"`。利用者が押すまで `session` は `preparing` のままで、`speechSource.start`（実 DOM では `SpeechRecognition.start`）は呼ばれず、Azure Speech の中継への音声の送信は 0 件。
